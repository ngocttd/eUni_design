Đặc tả yêu cầu phần mềm (SRS) — Frontend Cổng thông tin HUMG

Tài liệu này đặc tả yêu cầu cho phần giao diện người dùng (frontend) của Cổng thông tin điện tử Trường Đại học Mỏ - Địa chất. Cấu trúc theo IEEE/ISO 29148. Dùng cho đội phát triển frontend, QA và nghiệm thu.

1

Giới thiệu

1.1 Mục đích

Xác định đầy đủ, rõ ràng, kiểm thử được các yêu cầu chức năng và phi chức năng mà phần frontend của Cổng thông tin HUMG phải đáp ứng, làm cơ sở cho thiết kế chi tiết, lập trình, kiểm thử và nghiệm thu.

1.2 Phạm vi

Trong phạm vi: ứng dụng web một trang (SPA) gồm (a) website công khai — 11 khối nội dung + trang chủ + tin tức/sự kiện/media + tiện ích + liên hệ + tìm kiếm; (b) trang xác thực; (c) lớp vỏ (shell) và điều hướng của My eUni Portal (Sinh viên, Giảng viên, Phụ huynh, Lãnh đạo) và CMS; (d) hệ thống thiết kế và thư viện component dùng chung; (e) lớp tích hợp API (client).

Ngoài phạm vi: API/backend, cơ sở dữ liệu, hạ tầng máy chủ, hệ thống SSO, nội dung nghiệp vụ chi tiết bên trong từng màn hình portal/CMS, ứng dụng di động gốc.

1.5 Bố cục tài liệu

Mục 2 mô tả bối cảnh, người dùng, ràng buộc, giả định. Mục 3 đặc tả giao diện ngoài (UI, API, giao thức). Mục 4 liệt kê yêu cầu chức năng theo module, mỗi yêu cầu có mã, phát biểu, tiêu chí chấp nhận và mức ưu tiên. Mục 5 là yêu cầu phi chức năng. Mục 6 là ma trận truy vết. Mục 7 là phụ lục (danh mục route, Definition of Done).

2

Mô tả tổng thể

2.1 Bối cảnh sản phẩm

Frontend là một SPA React tách rời backend, giao tiếp qua REST/JSON. Hai lớp: công khai (không đăng nhập, phục vụ truyền thông – tuyển sinh – tra cứu) và eUni (portal cá nhân hoá + CMS, sau đăng nhập). Nội dung động do CMS cấp; dữ liệu nghiệp vụ do các hệ thống đào tạo/NCKH/thư viện cấp qua API. Hiện dữ liệu là mock trong src/data/*.js, sẽ thay bằng lớp API client.

2.2 Chức năng chính (tóm tắt)

  • Trình bày nội dung 11 khối công khai + trang chủ theo hệ thống thiết kế thống nhất, responsive.
  • Điều hướng đa cấp: header (5 dropdown + 3 link nhanh), section-nav khối, breadcrumb, footer, drawer mobile, tìm kiếm toàn cục, chuyển ngữ.
  • Danh sách có lọc / sắp xếp / phân trang và trang chi tiết cho: chương trình đào tạo, đề tài, công bố, chuyên gia, đối tác, dự án, CLB, hoạt động, tin tức, sự kiện, tài liệu thư viện, đơn vị, giảng viên.
  • Biểu mẫu công khai: liên hệ, tư vấn tuyển sinh, cơ hội hợp tác, đăng ký sự kiện.
  • Xác thực: đăng nhập SSO, đăng nhập phụ huynh, đăng nhập Microsoft 365, quên/đổi mật khẩu, quản lý phiên, bảo vệ route.
  • Vỏ portal & CMS: layout sidebar, chuông thông báo, thoát cổng, phân quyền route.

2.4 Môi trường vận hành

  • Trình duyệt: 2 phiên bản mới nhất của Chrome, Edge, Firefox, Safari (macOS); Safari iOS ≥ 15; Chrome Android ≥ 100. Không hỗ trợ Internet Explorer.
  • Thiết bị: điện thoại (≥ 320px), máy tính bảng, laptop/desktop (đến 1920px+).
  • Kết nối: hoạt động ổn định trên 3G/4G; tối ưu cho tải chậm.
  • Yêu cầu JavaScript bật. (Xem NFR-SEO-03 về prerender cho SEO.)

2.5 Ràng buộc thiết kế & triển khai

  • Công nghệ cố định: React 18, Vite 5, react-router-dom 6.26, CSS thuần với biến CSS (--humg-*). KHÔNG dùng thư viện UI component ngoài trừ khi được duyệt.
  • Hệ thống thiết kế: một tông navy #0a3d91 cho toàn bộ khối công khai; cam #ff9800 chỉ làm điểm nhấn nhỏ. Token định nghĩa tại src/index.css :root.
  • Bộ icon nội tuyến tự vẽ (src/lib/Icon.jsx), không phụ thuộc icon font.
  • Nguồn cấu trúc route & menu: src/routes/sitemap.js. Bỏ mục khỏi menu vẫn phải giữ route.
  • Ngôn ngữ giao diện: Tiếng Việt là chính, có bản Tiếng Anh (song song).
  • Mục tiêu tiếp cận: WCAG 2.1 mức AA.

2.6 Giả định & phụ thuộc

  • Backend cung cấp đầy đủ API theo danh sách ở tài liệu đi kèm (envelope {data, meta}, thời gian ISO-8601, ảnh đa kích thước + alt).
  • CMS cung cấp nội dung có cấu trúc cho từng khối và bài viết/sự kiện/media/banner/menu.
  • Hệ thống SSO và OAuth Microsoft 365 sẵn sàng; backend trả access + refresh token và thông tin vai trò.
  • Có CDN phục vụ ảnh/tài liệu; font tải từ Google Fonts hoặc self-host.

3

Yêu cầu giao diện ngoài

3.1 Giao diện người dùng

  • Hệ thống thiết kế: token màu / khoảng cách / bo góc / bóng / breakpoint theo tài liệu đi kèm §2. Mọi màu lấy từ token, không hardcode.
  • Layout shell: AppLayout (Header 2 tầng + Footer) cho công khai; AuthLayout (không header/footer) cho xác thực; PortalLayout (sidebar navy + topbar) cho eUni & CMS.
  • Khung trang khối: PageShell với 4 biến thể thân trang (mặc định / +sidebar / +section-nav / +cả hai).
  • Thư viện component dùng chung (~22): PageShell, SectionNav, Panel, TileGrid, DataTable, StatRow, Chips, FilterBar, Pagination, LinkList, SupportCard, MetaBar, NewsMini, DocList, StepList, Faq, HeroSearch, MediaCard, ArticleRow, ShareBar, Lightbox, Brand. Đặc tả props tại tài liệu đi kèm §4.
  • Breakpoint: 1280 / 1080 / 960 / 720 / 560 px (chi tiết NFR-COMPAT-02).

3.2 Giao diện phần cứng

Không có yêu cầu phần cứng riêng. Ứng dụng chạy trên trình duyệt của thiết bị người dùng (§2.4).

3.3 Giao diện phần mềm (API)

  • Giao tiếp REST/JSON, tiền tố /api/v1. Danh sách endpoint đầy đủ ở tài liệu đi kèm §8 (~130 endpoint, 11 nhóm).
  • Envelope: list { data: [], meta: { page, limit, total } }; detail { data: {} }. Lỗi: { error: { code, message, fields? } } + HTTP status chuẩn.
  • Tham số list dùng chung: page, limit, q, sort, lang.
  • Xác thực: header Authorization: Bearer <access> cho /me/* và eUni/CMS. OAuth 2.0 Authorization Code cho Microsoft 365.
  • Fonts: Google Fonts (Be Vietnam Pro, IBM Plex Mono — hoặc self-host). Icon: nội tuyến, không tải ngoài.

3.4 Giao diện truyền thông

  • Toàn bộ qua HTTPS. Nội dung tĩnh hỗ trợ ETag / Cache-Control; client dùng chiến lược stale-while-revalidate.
  • Thông báo portal: polling GET /me/notifications theo chu kỳ (khuyến nghị 60s) hoặc WebSocket/SSE nếu backend hỗ trợ (tuỳ chọn v1.1).
  • Tải file (biểu mẫu, tài liệu): tải trực tiếp qua URL lưu trữ (redirect từ API), không proxy qua frontend.

7.2 Definition of Done — mỗi trang

  • Khớp wireframe/mockup về bố cục & hệ thống thiết kế; dùng component dùng chung, không tạo biến thể trùng lặp.
  • Đủ 4 trạng thái: tải (skeleton) · có dữ liệu · rỗng · lỗi (có "Thử lại").
  • Responsive kiểm ở 360 / 768 / 1024 / 1440px, không cuộn ngang.
  • Bàn phím: tab đi hết các phần tử tương tác, focus rõ; modal/drawer bẫy & trả focus.
  • Kiểm axe/Lighthouse: Accessibility ≥ 95, không lỗi nghiêm trọng; tương phản đạt.
  • Đặt <title> + meta; liên kết nội bộ dùng <Link>; link ngoài rel="noopener".
  • Chuỗi qua i18n; ngày/số định dạng vi-VN.
  • Gọi đúng API theo tài liệu đi kèm §8; xử lý 401 → refresh/redirect, 403 → trang quyền, 404 → "không tìm thấy".
  • Không hardcode màu; không cảnh báo ESLint; có unit test cho logic không tầm thường.
  • Đã kiểm link chết trong phạm vi trang.
